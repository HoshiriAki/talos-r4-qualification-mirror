**先锋主义的载体收束（v1.1）：**

圆角矩形（8-16px）是"直角矩形"和"正圆"两个几何原始体之间的折中形状——历史上不属于构成主义/粗野主义任何一支（构成主义作品中"圆"作为几何原始体大量出现，但从不是"圆角矩形"这种暧昧过渡形；粗野主义"直角=诚实"的等式本身也是近年 Web Brutalism 潮流自己发明的标记，不是从建筑粗野主义严格继承来的教条）。构成主义本质上是一门平面构图和色彩语言（罗德钦科、李西茨基做的是海报、排版、宣传物料），当年根本不存在"圆角"这个设计问题——它是纯 2D 时代的产物。

**因此本系统对"先锋主义"的表达做以下收束：**

| 维度 | 隶属 | 说明 |
|------|------|------|
| **形状语言** | 设备/系统美学 | 采用圆角矩形（v1.1 圆角表），这是实用主义妥协，不强行论证符合先锋主义 |
| **色彩语言** | 先锋主义 | 继续严格继承构成主义——有限色板、高对比、色块硬碰撞（第二章色板体系不变） |
| **构图语言** | 先锋主义 | 继续严格继承构成主义——不对称网格、对角线、超大字号、刻意留白张力（第八章不变） |
| **运动语言** | 先锋主义 | 工业机械节奏 120ms 倍数（微交互保留），页面切换允许淡入+滑动（v1.1 软化） |
| **宣传物料** | 先锋主义 | Logo 展示页、启动页、Pitch Deck 封面、社交 banner——不受 App UI 可用性底线约束，可以比日常界面更激进地做纯先锋构图 |

形状语言让位给设备美学，构图和色彩语言留住先锋主义的魂，两条线互不干扰。

## 〇-B、设计优先级（当规则冲突时）

本规范包含大量规则。当规则冲突时，按以下优先级裁决——P0 覆盖 P1，依此类推。这个机制的用途是让 AI（或人类开发者）在不查文档的情况下做出正确取舍。

### P0 — 系统身份 · 绝不可违反

| 规则 | 说明 |
|------|------|
| 工业几何语言 | 编号系统 (MODULE-NN)、结构线、工程标注 |
| 有限色板 | 6 级暗色阶 + 唯一强调色 `#FF453A` + 4 功能色 |
| 材料诚实 | 色块不透明、硬偏移阴影、玻璃仅用于浮层 |
| 双字体 | Space Mono(骨架) + Inter(阅读) |

### P1 — 可用性 · 优先于视觉纯粹性

| 规则 | 说明 |
|------|------|
| 对比度 ≥4.5:1 | 正文/表格/表单——可读性是底线 |
| 触控目标 ≥44×44px | 移动端必须满足（桌面最小 36×36px） |
| 色盲友好 | 状态信息从不单独依靠颜色传达 |
| 焦点可见 | 所有交互元素有 2px accent 聚焦框 |
| `prefers-reduced-motion` | 全部动画降级为 0ms 瞬时切换 |

### P2 — 视觉语言

| 规则 | 说明 |
|------|------|
| 不对称 12 列网格 | 禁用等分（3:3:3:3, 6:6） |
| 超大字号 Hero 锚点 | 每页一个 |
| 字体层级 | KPI 36px Bold vs Body 14px Regular |
| 工业运动 | 微交互 120ms 正交，页面过渡 360ms fade+slide |
| 工业加载 | CAD/Wireframe/Assembly/Scan/Pipeline，不出现 Spinner |

### P3 — 装饰

| 规则 | 说明 |
|------|------|
| 背景氛围层 | 线框图标 + 工业指示灯，余光可见 |
| 宣传物料 | Logo 页/启动页/Pitch Deck——不受可用性约束 |
| 不是核心功能的视觉增强 | 允许裁切 |

### 冲突裁决示例

```
场景: 按钮设计

P2 (视觉) 说: 工业感要求 radius=0
P1 (可用性) 说: 触控安全建议 radius=8

P1 > P2 → radius = 8px (10px 实际)
采纳 P1 的触控友好，但保留 P2 的边框语言和填充色
```

```
场景: 加载动画

P2 (视觉) 说: 理想营造 CAD Loading 建造序列 (600ms)
P1 (可用性) 说: 数据加载不应超过 300ms 感知延迟

P1 > P2 → 数据已就绪时跳过建造序列直接展示
仅在真实延迟 > 500ms 时触发加载动画
```

```
场景: 背景氛围层光点

P3 (装饰) 说: 多路径并发光点更有产线运转感
P0 (系统身份) 说: 每个视觉元素必须有结构意义
P1 (可用性) 说: 背景层必须余光可见，不能抢 Hero 锚点

P0 > P1 > P3 → 光点仅响应真实网络请求，亮度压低，单点巡游
```

- SaaS 可用性是底线——如果操作效率下降，先锋主义让步

## 二、色彩体系

### 2.1 设计原则

```
        SaaS 系                          Brutalist 系
  多级灰阶 + 多强调色    ──── 融合 ────→   限制色板 + 严格角色
  色彩丰富 = 信息量大                    每个颜色必须有结构意义
```

**用色铁律：**
1. 每一个色值必须有一个明确的**结构角色**
2. 不允许"装饰性"的颜色
3. 强调色仅一种，且仅用于交互状态和关键数据
4. 灰阶精确为 6 级，每级间距相等
5. 无渐变应用于色块——所有实色填充是绝对的、平坦的（v1.1：边缘高光渐变、玻璃层的透明叠加属材质效果，不违反此条）

## 三、字体排版

### 3.1 双字体策略

| 用途 | 字体 | 理由 |
|------|------|------|
| **标题 / 数据 / 导航 / 代码 / 编号** | **Space Mono** | 粗野主义的等宽基因——结构的骨骼 |
| **正文 / 表格内容 / 长文本 / 表单** | **Inter** | SaaS 场景下的可读性——信息的肌肉 |

**规则：**
- 所有标题级别、数字读数、导航文字、代码/ID、模块编号 = Space Mono
- 所有正文段落、表格内容、表单标签、描述文字、提示信息 = Inter
- 按钮文字根据上下文：主要 CTA 用 Space Mono（结构感），次要操作用 Inter（可读性）
- 数字必须等宽——Space Mono 天然保证

### 3.2 字重与大小阶梯

| 层级 | 字体 | 字重 | 大小 / 行高 | 用途 |
|------|------|------|-------------|------|
| **Hero** | Space Mono | 700 | 48-120px / 1.1 | 页面主视觉数字/标题（先锋构图） |
| **H1** | Space Mono | 700 | 28px / 1.2 | 页面主标题 |
| **H2** | Space Mono | 700 | 22px / 1.3 | 区域标题 |
| **H3** | Space Mono | 600 | 16px / 1.4 | 卡片标题 |
| **KPI** | Space Mono | 700 | 36px / 1.1 | 核心指标大字 |
| **DATA** | Space Mono | 600 | 18px / 1.3 | 次要数据读数 |
| **Body L** | Inter | 500 | 15px / 1.5 | 正文、列表项 |
| **Body** | Inter | 400 | 14px / 1.5 | 表格内容、描述 |
| **Body S** | Inter | 400 | 12px / 1.5 | 辅助文字、时间戳 |
| **Caption** | Space Mono | 500 | 11px / 1.4 | 标签、全大写标识、编号 |
| **Code** | Space Mono | 400 | 13px / 1.6 | 代码块、订单号、设备号、模块编号 |

### 3.3 排版原则

1. **Space Mono 是结构的骨骼：** 页面中所有 Space Mono 元素告诉眼睛"这里有关键信息"
2. **Inter 是信息的肌肉：** 表格行、长描述、表单标签使用 Inter 确保不疲劳
3. **数字必须等宽：** 用 Space Mono 天然保证所有数字对齐
4. **标题使用全大写可选：** H1 和 Caption 推荐全大写，中间级别不强制
5. **字重跳跃：** KPI (700) 对 Body (400) 的粗细比 = 1.75:1，形成强烈的结构对比
6. **中文使用全字间距：** 标题级中文可设 letter-spacing: 0.25-0.5em，成为几何块
7. **编号使用固定宽度：** 所有模块编号（MODULE-01 等）使用 Space Mono 等宽

## 四、边框与间距

### 4.1 核心原则（v1.1）

```
圆角：   8-16px 全面圆角 — 与设备/系统美学和谐（v1.1 实用主义妥协）
阴影：   硬直角偏移阴影 — 无模糊，仅纯色偏移（v1.1 替代零阴影）
渐变：   色块填充禁渐变 — 边缘高光渐变属材质效果，不违反此条
透明度： 仅用于浮起临时层 — 玻璃态（导航/侧边栏/弹窗/下拉/通知），信息承载层不透明
```

### 4.2 圆角系统（v1.1）

| 元素 | 圆角 | 说明 |
|------|------|------|
| 卡片（标准/强调/焦点/警示） | **12px** | 主要信息容器 |
| 按钮（Primary/Secondary/Danger） | **10px** | 交互元素 |
| 按钮（Ghost/Text） | **8px** | 低权重交互 |
| 输入框/选择器 | **8px** | 表单元素 |

### 4.6 阴影 — 硬直角偏移（v1.1）

```
/* 硬直角偏移 — 无模糊，无渐变 */
--shadow-offset-default: 4px 4px 0px var(--border-strong);
--shadow-offset-accent:  4px 4px 0px var(--accent);
--shadow-offset-hover:   6px 6px 0px var(--accent);  /* 悬停偏移增大 */
```

**规则：**
1. `box-shadow` 不带第三个 blur 参数（永远是 0px 模糊）
2. 偏移方向固定为右下（X+ Y+），制造"卡片被顶起"的机械反馈感
3. 标准卡片用 `border-strong` 色偏移，强调/焦点卡片用 `accent` 色偏移
4. 悬停时偏移距离增大 2px，与 v1.0 平移 2-3px 的悬停手法叠加使用
5. 浮层（Dialog/Dropdown）可选择 `8px 8px 0px` 更大偏移以强调层级

**深度达成方式（v1.1 三通道）：**
1. 色块明度对比（bg-base → bg-surface → bg-elevated）——不变
2. 边框粗细变化（1px → 2px）——不变
3. 硬偏移阴影的纯色色差（第三维视觉落地感）——v1.1 新增

### 4.7 玻璃态材质 Token（v1.1 新增）

```css
/* ── 玻璃基色（暗色主题） ─────────────────────────────────── */
--glass-bg-surface:   rgba(22, 22, 24, 0.55);
--glass-bg-elevated:  rgba(30, 30, 34, 0.65);
--glass-blur:         24px;
--glass-border:       1px solid rgba(255, 255, 255, 0.08);

/* ── 边缘高光 — 真正"卖"玻璃感的要素 ──────────────────────── */
--glass-highlight: linear-gradient(
  180deg,
  rgba(255, 255, 255, 0.15) 0%,
  rgba(255, 255, 255, 0) 40%
);
/* 应用于玻璃面板顶部边缘，1px 高，模拟光线打在玻璃边缘的亮线 */

/* ── 玻璃使用规则 ────────────────────────────────────────── */
/* ✅ 玻璃适用：浮起来的临时表面 */
/*   · 导航栏 · 侧边栏 · 下拉菜单 · 弹窗 · 通知条 · 背景氛围层 */
/* ❌ 玻璃不适用：承载信息本身的底层 */
/*   · 数据卡片 · 表格 · 图表容器 · 正文区域 */
/* 理由：卡片/表格用玻璃会导致文字对比度随背景波动 + 所有元素同材质丢失层级感 */
```

**为什么玻璃显得"高级"而不是"廉价灰盒子"（v1.1 手艺细节）：**

1. **模糊背后必须有内容可透，不能是空的。** 一个纯色背景上放玻璃层，模糊后就是一块颜色浅一点的灰盒子，不会有玻璃感。背景氛围层（§七-A）的存在给了玻璃"透过去有东西"的画面——两个决定互相成就。

2. **边缘高光比模糊本身更决定质感。** 玻璃在现实里看起来像玻璃，是因为光线打在边缘上会有一条亮线。`--glass-highlight` 渐变描边这条线比 blur 参数本身更决定"高不高级"。

3. **玻璃只用在"浮起来的临时表面"，不用在"承载信息的底层"。** 导航栏、侧边栏、弹窗、通知条——这些东西的角色本来就是"浮在内容上面的临时表面"，玻璃合适。数据卡片、表格——这些是承载信息本身的东西，文字可读性会随背景内容飘忽不定，且所有东西都是同一种材质时层级感反而消失。

### 5.3 卡片合规检查表

**Must（必须）:**
- 使用 CSS 变量 token（`var(--bg-surface)` 不是 `#161618`）
- 12px 圆角
- 1px/2px 边框（不是无边框）
- 硬偏移阴影（不是模糊阴影）
- 标题用 Space Mono，正文用 Inter

**Must Not（禁止）:**
- 玻璃/半透明背景 (`glass-bg`/`backdrop-filter`)
- 无边框的纯色块卡片
- 模糊阴影 (`box-shadow` 第三个参数 > 0)
- 渐变背景 (`linear-gradient` / `radial-gradient`)
- 装饰性颜色（不用 token 的任意 hex）
- 圆角 ≠12px（图表容器可以用 `--radius-sm` 4px）

## 八、先锋主义构图语言

### 8.1 阅读路径重设计

传统 SaaS 的阅读路径是 F 型扫描。Industrial Avant UI 的阅读路径是**海报式的**：

```
      TITLE ────────────────────────────────   ← 第一眼：巨大的空间锚点
           │
      subtitle                                 ← 第二眼：被推向边缘
           │
  ─────────────────────────────────────────    ← 第三眼：结构线引导视线
           │
      03 ───────────────────── MODULE A       ← 第四眼：编号系统
           │
  /////////////////////////////////////////    ← 第五眼：分隔语言
           │
      ████████████                             ← 第六眼：核心数据块
           │
      BUTTON                                   ← 最后：行动
```

**规则：**
1. 每个页面必须有一个 **Hero 锚点**（一个巨大数字、一个巨大标题、一个 3D 模型、一个流程）
2. 视线路径由结构线引导，不由卡片边界引导
3. 信息不是等权的——有明确的"主角"和"配角"
4. 配角信息被刻意推到边缘，但不消失

### 8.2 信息编号系统

来源：工业蓝图、NASA 技术手册、产品说明书

| 层级 | 格式 | 示例 | 位置 |
|------|------|------|------|
| 页面 | `MODULE-NN` | `MODULE-01` | 页面左上角，小号 Space Mono |
| 子系统 | `SYS_NN` | `SYS_02` | 区域标题旁边 |
| 组件 | `A-NN` / `B-NN` | `A-03` | 卡片角落 |
| 版本 | `YYYY — VN.NN — REV.N` | `2026 — V1.04 — REV.3` | 页面底部 |
| 区域 | `ZONE_X` | `ZONE_A` | 侧边栏或 Header |
| 数据流 | `DATA_FLOW_NN` | `DATA_FLOW_07` | 流线标签 |
| 节点 | `NODE_NN` | `NODE_05` | 连接节点旁 |

**编号不是装饰。** 每个编号对应一个可定位的功能模块。在帮助文档、错误排查、日志中，编号作为功能定位符使用。

### 8.3 超大字体构图

字体不仅传达信息——字体的**位置、大小、方向**本身就是构图元素。

**规则：**
1. 页面标题可以跨越 3-4 个卡片宽度（Space Mono, Bold, 48-64px）
2. 核心数字（如总设备数、今日收入）可以放大到 80-120px，成为视觉主角
3. 数字和标题可以故意偏离左对齐——右对齐、居中、甚至轻微越界
4. 大字体可以**穿透**卡片边界（字压在卡片上方，但卡片仍然可交互）
5. 中文标题使用全字间距（letter-spacing: 0.25-0.5em），成为几何块

### 8.4 不对称布局

来源：构成主义海报、瑞士网格的非对称变体

```
禁止：
┌────────┬────────┐
│        │        │   2×2 对称网格
├────────┼────────┤   所有卡片等权
│        │        │   所有卡片等大
└────────┴────────┘

鼓励：
┌──────────────────┬────────┐
│                  │        │
│       6          │   3    │   6+3+2+1 视觉节奏
│                  │        │
├────────┬─────────┴────────┤
│   2    │                  │
│        │       1          │
└────────┴──────────────────┘
```

**规则：**
1. 每行最多一个"英雄卡片"（占 6-8 列），旁边配 1-2 个小卡片（占 2-4 列）
2. 同一页面中，两个卡片极少等宽
3. 列数比例推荐：`6:3:2:1`、`8:4`、`5:4:3`、`7:5`
4. 禁用：`3:3:3:3`、`4:4:4`、`6:6`
5. 但不对称不等于混乱——网格仍然是 12 列，只是列的分配不均匀
6. 70% 留白，30% 内容——来源：06 红色界面的核心吸引力

### 8.5 结构线系统

来源：建筑制图、工业蓝图、NASA 技术图纸

结构线**贯穿整个页面**，不局限于卡片内部。

| 线型 | 视觉 | 用途 |
|------|------|------|
| 主结构线 | `2px solid border-strong` | 页面级区域分隔 |
| 次结构线 | `1px solid border-base` | 区域内模块分隔 |
| 引导线 | `1px dashed text-tertiary` | 编号 → 组件的引线 |
| 参考线 | `1px dotted text-tertiary` | 页面基准线（可选） |
| 坐标标记 | 小十字 `+` | 结构线端点（制图语言） |

**规则：**
1. 每个页面至少一条贯穿全宽的主结构线
2. 编号系统与结构线交叉——"交点"成为视觉定位点
3. 结构线可以穿越卡片、文字和空白区域
4. 结构线的端点使用小十字 `+` 标记

### 8.6 刻意张力

来源：构成主义的"不舒适但平衡"

**规则：**
1. 一行中的三列文字可以使用不同对齐方式（L/C/R 混合）
2. 卡片可以轻微重叠或越界（但不超过 8px，不影响点击）
3. 线条可以穿越组件边界（结构线不受卡片约束）
4. 数字的大小比例可以极端——一个大数字（120px）旁边放一个小数字（14px）
5. 张力是调料，不是主菜——每页 1-3 处张力点，不能更多

## 九、运动语言

### 9.1 运动原则

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   运动不是装饰。运动是结构的第四维度。                          │
│                                                             │
│   允许的运动：                                               │
│   · 正交方向的平移（上下左右，90°）                            │
│   · 顺序揭示（像蓝图的绘制过程）                               │
│   · 宽度/高度的线性增长                                      │
│   · 颜色/边框的状态切换（瞬时）                                │
│                                                             │
│   禁止的运动：                                               │
│   · 任何曲线路径                                             │
│   · 缩放（scale）——除了 3D 场景                               │
│   · 旋转（rotate）——除了 3D 场景                              │
│   · 淡入淡出（fade/opacity）——用平移或边框变化替代             │
│   · 弹性/弹跳（spring/bounce）                               │
│   · 任何贝塞尔缓动曲线                                       │
│                                                             │
│   节奏规则：                                                 │
│   所有动画时长必须是 120ms 的整数倍                            │
│   120ms / 240ms / 360ms / 480ms                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 9.2 工业节奏

来源：PLC 控制器、机械冲压、电子继电器

```
   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
   │ 120  │   │ 120  │   │ 240  │   │ 120  │
   │ 进场  │   │ 停顿  │   │ 展开  │   │ 就位  │
   └──────┘   └──────┘   └──────┘   └──────┘

   啪 ... 啪 ... 啪——啪 ... 啪
   机械冲压的节奏，不是钢琴的节奏
```

**时长表：**

| 动作 | 时长 | 说明 |
|------|------|------|
| 边框状态切换 | 0ms（瞬时） | 颜色变化不需要时间 |
| 微小位移（hover） | 120ms | 2-4px 的平移 |
| 模块入场 | 240ms | 正交滑入 |
| 结构线绘制 | 360ms | 横线/竖线从一端到另一端 |
| 数据扫描填充 | 480ms | 逐行填充表格或列表 |
| 页面过渡-遮罩 | 360ms | 正交遮罩滑过 |
| 页面过渡-重组 | 480ms | 新页面的模块依次入场 |
| 图表渲染 | 600ms | 坐标轴 → 刻度 → 数据 |

### 9.3 构成主义运动

元素不应该"出现"——它们应该**被建造**。

```
Phase 1: 框架 (120ms)    Phase 2: 填充 (240ms)

┌──────────────────┐     ┌──────────────────┐
│ ──────────────── │     │ ████████████████ │
│ │               │     │ ████████████████ │
│ │               │     │ ████████████████ │
│ ──────────────── │     │ ████████████████ │
└──────────────────┘     └──────────────────┘
  边框先行                 内容填充

Phase 3: 编号 (360ms)    Phase 4: 数据 (480ms)

┌──────────────────┐     ┌──────────────────┐
│ ████████████████ │     │ 24  ████████████ │
│ ████████████████ │     │ +12% ███████████ │
│ ████████████████ │     │ A-01 ███████████ │
│ A-01             │     │                  │
└──────────────────┘     └──────────────────┘
  编号标签出现             数据填充就位
```

**规则：**
1. 每次运动是**可辨识的阶段**，不是连续的缓动
2. 阶段之间有微小停顿（"机械节拍"）
3. 运动方向固定：结构线从左到右或从上到下，填充从底部到顶部或从左侧到右侧
4. 编号和数据在框架之后出现——"先有结构，后有内容"

### 9.4 正交运动

来源：工业机械臂、XY 绘图仪、数控机床

```
所有运动只能是水平或垂直方向。

禁止：↗ ↘ ↙ ↖
允许：→ ← ↑ ↓

折线运动：
  → → → ↓
  不是 ╰（曲线）

正确：                  错误：
  ────────               ╭──────╮
          │               │      │
          │               │      ▼
          ▼               ╰──────╯
```

**方向语义：**
- `→` = 前进、展开、进入
- `←` = 后退、收起、退出
- `↓` = 展开详情、下拉
- `↑` = 收起详情、提交

### 9.5 悬停语言

不是阴影浮起——而是**机械设备的微响应**。

**微响应序列：**
1. 编号颜色变化（0ms）← accent 色瞬间亮起
2. 边框加粗/变色（0ms）
3. 元素整体平移 2-3px（120ms）← 正交方向
4. 关联信息出现（240ms）

```
按钮 hover：
┌────────────┐          ┌────────────┐
│   确认      │   →      │   确认      │
└────────────┘          └────────────┘
                          编号亮起
                          边框加粗 1px→2px
                          轻微右移 2px

卡片 hover：
┌──────────────────────┐
│ A-03                 │  ← 编号: text-tertiary → accent
│ ──────────────────── │  ← 标题下划线: border-base → accent
│                      │
│ 内容...              │  ← 内容不变
│                      │
└──────────────────────┘
  边框: border-base → border-strong
  整体: 向右平移 3px
```

### 9.6 页面过渡语言（v1.1）

v1.0 要求纯正交遮罩过渡，v1.1 允许淡入+滑动组合。

| 过渡类型 | v1.1 规则 | 缓动 |
|----------|----------|------|
| **页面切换（路由级）** | 淡入+滑动组合（fade + translateX 48px） | `cubic-bezier` 允许 |
| **悬停微交互** | **保留 v1.0 不变** — 编号高亮/边框加粗/按钮位移 120ms | 瞬时或无缓动 |
| **模块内部状态切换**（表格行展开、Tab 切换） | 正交平移 | 保留 v1.0 |
| **背景氛围层过渡** | 淡入淡出，独立于前景内容节奏 | `cubic-bezier` 允许 |

```
路由级页面切换:
  fade (0 → 1, 360ms) + slide (48px → 0, 360ms)
  cubic-bezier(0.4, 0, 0.2, 1) 允许
  
  不是 Fade 300ms，也不是纯正交遮罩
  是"滑动中带淡入"的工业节奏感
```

## 十一、空间信息界面（3D 场景）

### 11.1 渲染模式：Wireframe-on-Solid

**规则：**
1. 所有 3D 面使用纯色填充，不使用渐变或纹理
2. 可见边使用 1px 描边（`3d-edge`）
3. 辅助线/构造线使用虚线（`3d-guide`）
4. 关键节点使用小方块标记（非球体——保持几何语言一致）
5. 不使用任何光照/阴影/环境光遮蔽
6. 透视类型：等角投影（Isometric）或正射投影（Orthographic），不使用透视投影

## 十四、背景氛围层（v1.1 新增）

### 14.0 设计哲学

背景层不是纯装饰——它是系统真实状态的低强度可视化。其视觉语言继承自第七章数据可视化语法（桑基图"直线连接、无曲线"，方块节点），和第十章加载系统（Wireframe → 描边 → 填充的建筑感），不是额外发明的装饰语言。这种复用关系让整个系统更自洽——功能层和氛围层是同一套语法在不同场景的运用。

### 14.1 视觉构成

- **图标本体：** 当前页面 Icon 的线框轮廓（呼应 Loading 系统"构造线"语言）。线常态使用 `--3d-guide` 或 `border-base` 色阶——暗色、低对比、余光可见。
- **走线路径：** 图标轮廓拆解为若干条"电路/管线"路径（类似 PCB 走线或 P&ID 管线图逻辑），不是自由曲线。呼应第七章桑基图"直线连接、无曲线、连接点=小方节点"规范。
- **路径交汇点：** 复用现有状态方块语言（8×8px 方块，4px 微圆角）。常态为暗色空心方块（`border-base` 描边），信号经过时短暂点亮为实心 `accent`。

### 14.2 动效技术

- 光沿路径传播：SVG `stroke-dasharray` + `stroke-dashoffset` 位移动画。线常暗（`border-base` 或 `3d-guide`），一小段亮点（accent 色，可带轻微发光模糊——这里的模糊是光源本身，不是层次叠加，与"透明不禁用于层次表达"原则不冲突）沿路径移动。
- 交汇点信号经过后：熄灭（更像"实时信号"的即时感）或保留微弱常亮（更像"线路已激活过"的记忆感）。默认按熄灭处理。

### 14.3 密度与可见度底线

**背景层的动，永远只能是余光可见，不能是视线第一落点。** 数量和亮度必须刻意压低，任何时候不能和页面 Hero 锚点或前景 accent 争夺视觉重心。

| 模式 | 说明 |
|------|------|
| 单点巡游 | 一个光点沿整个图标路径慢速巡游——安静、克制，适合背景层不抢主角 |
| 多路径并发 | 多条支线同时有活动光点——更有"系统在真实运行"的说服力，但需非常克制亮度和频率 |

### 14.4 网络请求可视化（v1.1）

背景层同时承担"当前网络请求活动可视化"的功能——背景不是演出来的，它在物理意义上真的在显示系统正在做什么。

**真实信号为主，加极轻微"心跳"防止背景显死。**

| 规则 | 详情 |
|------|------|
| 真实请求 | 网络请求发生时，对应路径触发信号脉冲（亮度、路径长度正常） |
| 心跳触发 | 仅在**≥8 秒无真实请求**时触发（具体数值待联调时调优） |
| 心跳强度 | 脉冲亮度和路径长度必须**明显弱于**真实信号——避免用户分不清"真实请求"和"系统在演" |
| 设计态度 | 这是从"材料诚实，反装饰"系统底线做的**一次明确记录在案的妥协**——心跳的作用是"防止背景显死"，不是"模拟活动" |

### 14.5 语义化映射（二期可选）

不同背景路径/区域对应不同子系统（订单、库存、通知等，复用 `SYS_NN` 编号体系），对应子系统的 API 被调用时，只有那条路径亮起。这样背景层实质上变成一张**实时系统活动地图**。需要事件总线将前端网络层请求映射到具体路径，工程量比通用脉冲版本高。一期先上通用脉冲版本跑通视觉效果。

## 十六、可访问性

### 16.1 对比度保证

| 关系 | 对比度 | 标准 |
|------|--------|------|
| text-primary (#FFF) / bg-base (#0D0D0F) | ~18:1 | AAA ✓ |
| text-secondary (#A0A0A8) / bg-surface (#161618) | ~6:1 | AA ✓ |
| accent (#FF453A) / bg-surface (#161618) | ~4.5:1 | AA ✓ |
| text-tertiary (#6A6A72) / bg-surface | ~3.5:1 | 仅用于装饰/禁用 |

### 焦点指示器
- 所有可交互元素必须有可见的 2px accent 边框聚焦状态
- 不使用浏览器默认的 outline（通常带圆角），自定义方形焦点框

### 色盲友好
- 状态信息从不单独依靠颜色传达
- 每个状态指示器配合文字标签
- 图标 + 颜色 + 文字三通道编码
- 警示条纹提供第二通道的视觉识别

### 动效可访问性
- 尊重 `prefers-reduced-motion`：所有动画降级为 0ms 瞬时切换
- 加载状态提供文字说明（非纯视觉）

### v1.1 新增决策（#14-#20）

| # | 决策 | 理由 |
|---|------|------|
| 14 | 圆角改为 8-16px 全面圆角 | 与设备/系统圆角美学和谐，明确为实用主义妥协。构成主义是纯 2D 产物，"圆角"问题历史上不属于它 |
| 15 | 零阴影 → 硬直角偏移阴影 | 圆角化后需要视觉落地感，偏移阴影保持"无模糊无渐变"的材料诚实底线 |
| 16 | 透明度铁律软化，引入玻璃层 | 仅用于导航/侧边栏/弹窗等浮起临时层；卡片/表格等信息承载层保持不透明 |
| 17 | 页面切换允许淡入+滑动 | 路由级过渡用 fade+slide+cubic-bezier；悬停微交互等高频反馈仍保留 120ms 正交节奏，避免机械感整体消失 |
| 18 | 先锋主义收束于色彩与构图 | 形状语言让位给设备美学；先锋主义的魂在色彩（有限色板+高对比）和构图（不对称网格+超大字号+留白张力） |
| 19 | 背景氛围层引入线框图标+工业指示灯 | 复用数据可视化语法（桑基图直线+方块节点）和 Loading 系统（Wireframe 语言），不是额外发明的装饰层 |
| 20 | 背景层心跳机制 | 真实信号为主，心跳仅在 ≥8s 无请求时以明显弱化的强度出现。是从"材料诚实"底线的**明确妥协**，需在代码注释中标注 |
| 21 | P0-P3 设计优先级 | 当规则冲突时按优先级裁决：P0 系统身份 > P1 可用性 > P2 视觉语言 > P3 装饰。解决"按钮要工业感=直角 vs 触控要求=圆角"这类冲突，让 AI 不查文档也能做出正确取舍 |
