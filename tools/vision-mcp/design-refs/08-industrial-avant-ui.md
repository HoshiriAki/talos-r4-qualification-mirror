## 一、三层架构

### 1.1 职责分离

```
      ┌─────────────────────────────────────────────┐
      │                                             │
      │   BRUTALISM        AVANT-GARDE              │
      │   (静态)            (运动)                   │
      │                                             │
      │   页面静止时         用户操作时               │
      │   由粗野主义主导      由先锋主义主导            │
      │                                             │
      │   ┌─────────┐      ┌─────────┐              │
      │   │ 布局    │      │ 构图     │              │
      │   │ 边框    │      │ 运动     │              │
      │   │ 卡片    │      │ 节奏     │              │
      │   │ 色板    │      │ 空间     │              │
      │   │ 字体    │      │ 张力     │              │
      │   └─────────┘      └─────────┘              │
      │        │                │                   │
      │        └───────┬────────┘                   │
      │                │                            │
      │         MODERN SAAS                         │
      │         (可用性)                              │
      │                                             │
      │         · 可读性 · 效率 · 学习成本 · 无障碍    │
      │                                             │
      └─────────────────────────────────────────────┘
```

**核心规则：**
- 静止页面不能让先锋主义破坏可读性
- 先锋主义通过**运动**来体现，不通过将静止页面变难读来体现
- SaaS 可用性是底线——如果操作效率下降，先锋主义让步

### 1.2 什么时候先锋主义出现

| 时机 | 先锋主义的角色 | 手段 |
|------|---------------|------|
| **页面加载** | 建筑建造般的入场 | 线框 → 描边 → 填充 → 编号 → 数据（Assembly Loading） |
| **区域切换** | 构成主义平移 | 正交滑动，模块化入场 |
| **数据更新** | 管道/扫描流 | 信息扫描线、数据管道动画 |
| **悬停交互** | 机械设备响应 | 编号亮起、边框移动、轻微位移 |
| **页面过渡** | 空间重组 | Grid → Mask → Module → Number → Complete |
| **图表渲染** | 蓝图绘制 | 坐标轴先出现 → 刻度标记 → 数据描点 → 连线 |
| **空状态** | 建筑工地 | 构造线 + 占位编号 + 网格参考面 |
| **加载/处理中** | 工业扫描 | Wireframe Loading, CAD Loading, Assembly Loading |

## 三、先锋主义构图语言（Avant-garde Composition）

这是 07 文档**完全缺失**的章节。它定义的不是"组件长什么样"，而是"页面如何被观看"。

### 3.1 阅读路径重设计

传统 SaaS 的阅读路径是 F 型扫描：

```
Logo           ← 第一眼
Title          ← 第二眼
Description    ← 第三眼
Button         ← 第四眼
```

Industrial Avant UI 的阅读路径是**海报式的**：

```
      TITLE ────────────────────────────────   ← 第一眼：巨大的空间锚点
           │
      subtitle                                 ← 第二眼：被推向边缘
           │
  ─────────────────────────────────────────    ← 第三眼：结构线引导视线
           │
      03 ───────────────────── MODULE A       ← 第四眼：编号系统
           │
  /////////////////////////////////////////    ← 第五眼：分隔语言
           │
      ████████████                             ← 第六眼：核心数据块
           │
      BUTTON                                   ← 最后：行动
```

**规则：**
1. 每个页面必须有一个 **Hero 锚点**（一个巨大数字、一个巨大标题、一个 3D 模型、一个流程）
2. 视线路径由结构线（横线、竖线、编号）引导，不由卡片边界引导
3. 信息不是等权的——有明确的"主角"和"配角"
4. 配角信息被刻意推到边缘，但不消失

### 3.2 信息编号系统（Information Numbering）

来源：工业蓝图、NASA 技术手册、产品说明书

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   MODULE-01                     SYS_02                      │
│   订单管理                       定价引擎                     │
│                                                             │
│   WAREHOUSE_A                   ZONE_B                      │
│   总仓                          设备列表                     │
│                                                             │
│   2026 — V1.04 — REV.3                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**编号规则：**

| 层级 | 格式 | 示例 | 位置 |
|------|------|------|------|
| 页面 | `MODULE-NN` | `MODULE-01` | 页面左上角，小号 Space Mono |
| 子系统 | `SYS_NN` | `SYS_02` | 区域标题旁边 |
| 组件 | `A-NN` / `B-NN` | `A-03` | 卡片角落 |
| 版本 | `YYYY — VN.NN — REV.N` | `2026 — V1.04 — REV.3` | 页面底部 |
| 区域 | `ZONE_X` | `ZONE_A` | 侧边栏或 Header |

**编号不是装饰。** 每个编号对应一个可定位的功能模块。在帮助文档、错误排查、日志中，编号作为功能定位符使用。

### 3.3 超大字体构图（Giant Typography）

字体不仅传达信息——字体的**位置、大小、方向**本身就是构图元素。

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                                                              │
│     设    备    管    理                                      │
│                                                              │
│                                    01                        │
│                                                              │
│                          2026                                │
│                                                              │
│  ───────────────────────────────────────────────────────    │
│                                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐       │
│  │          │ │          │ │          │ │          │       │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘       │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**超大字体使用规则：**
1. 页面标题可以跨越 3-4 个卡片宽度（Space Mono, Bold, 48-64px）
2. 核心数字（如总设备数、今日收入）可以放大到 80-120px，成为视觉主角
3. 数字和标题可以故意偏离左对齐——右对齐、居中、甚至轻微越界
4. 大字体与卡片的关系：它可以**穿透**卡片边界（字压在卡片上方，但卡片仍然可交互）
5. 中文标题使用全字间距（letter-spacing: 0.5-1em），成为几何块

### 3.4 不对称布局（Asymmetric Layout）

来源：构成主义海报、瑞士网格的非对称变体

```
禁止：
┌────────┬────────┐
│        │        │   2×2 对称网格
├────────┼────────┤   所有卡片等权
│        │        │   所有卡片等大
└────────┴────────┘

鼓励：
┌──────────────────┬────────┐
│                  │        │
│       6          │   3    │   6+3+2+1 视觉节奏
│                  │        │
├────────┬─────────┴────────┤
│   2    │                  │
│        │       1          │
└────────┴──────────────────┘
```

**不对称规则：**
1. 每行最多一个"英雄卡片"（占 6-8 列），旁边配 1-2 个小卡片（占 2-4 列）
2. 同一页面中，两个卡片极少等宽
3. 列数比例推荐：`6:3:2:1`、`8:4`、`5:4:3`、`7:5`
4. 禁用：`3:3:3:3`、`4:4:4`、`6:6`
5. 但不对称不等于混乱——网格仍然是 12 列，只是列的分配不均匀

### 3.5 结构线系统（Structural Guides）

来源：建筑制图、工业蓝图、NASA 技术图纸

结构线**贯穿整个页面**，不局限于卡片内部：

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  ───────────────────────────────────────────────────────    │  ← 页面级横结构线
│                                                              │
│  MODULE-01                                                   │
│                                                              │
│  │                                                           │  ← 页面级竖结构线
│  │   ┌──────────────────────────────────┐                   │
│  │   │                                  │                   │
│  │   │        CONTENT ZONE              │                   │
│  │   │                                  │                   │
│  │   └──────────────────────────────────┘                   │
│  │                                                           │
│  │                         A-01 ──────────                   │  ← 编号 + 引线
│  │                                                           │
│  ───────────────────────────────────────────────────────    │
│                                                              │
│  2026 — V1.04 — REV.3                                       │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**结构线类型：**

| 线型 | 视觉 | 用途 |
|------|------|------|
| 主结构线 | `2px solid border-strong` | 页面级区域分隔 |
| 次结构线 | `1px solid border-base` | 区域内模块分隔 |
| 引导线 | `1px dashed text-tertiary` | 编号 → 组件的引线 |
| 参考线 | `1px dotted text-tertiary` | 页面基准线（可选） |
| 坐标标记 | 小十字 `+` | 结构线端点（来源：制图） |

**规则：**
1. 每个页面至少一条贯穿全宽的主结构线
2. 编号系统与结构线交叉——"交点"成为视觉定位点
3. 结构线可以穿越卡片、文字和空白区域
4. 结构线的端点使用小十字 `+` 标记（制图语言）

### 3.6 刻意张力（Intentional Tension）

来源：构成主义的"不舒适但平衡"

```
例 1：文字对齐故意混合

  LEFT 对齐 ─────────────────────────
                     CENTER ─────────
                                         RIGHT ─────────

例 2：元素轻微越界

  ┌──────────────────────┐
  │                      │
  │  ┌───────────────────│────┐
  │  │ 卡片 A            │    │
  │  │                   │    │
  └──│───────────────────┘    │
     │                        │
     │      卡片 B             │
     │                        │
     └────────────────────────┘

例 3：数字跨栏

  ┌──────────┬──────────┬──────────┐
  │          │          │          │
  │   24     │   893    │   001    │
  │          │          │          │
  └──────────┴──────────┴──────────┘

  24 = 左对齐
  893 = 居中对齐
  001 = 右对齐

  三个数字在相邻列中，但对齐方式不同
  制造"不舒适但有序"的视觉节奏
```

**张力规则：**
1. 一行中的三列文字可以使用不同对齐方式（L/C/R 混合）
2. 卡片可以轻微重叠或越界（但不超过 8px，不影响点击）
3. 线条可以穿越组件边界（结构线不受卡片约束）
4. 数字的大小比例可以极端——一个大数字（120px）旁边放一个小数字（14px）
5. 张力是调料，不是主菜——每页 1-3 处张力点，不能更多

## 四、运动语言（Motion Language）

这是 07 文档**完全缺失**的章节。这里的运动不是 Material Design 的 easing curve，而是**构成主义的机械节奏**。

### 4.1 运动原则

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   运动不是装饰。运动是结构的第四维度。                          │
│                                                             │
│   在 Industrial Avant UI 中：                                │
│                                                             │
│   允许的运动：                                               │
│   · 正交方向的平移（上下左右，90°）                            │
│   · 顺序揭示（像蓝图的绘制过程）                               │
│   · 宽度/高度的线性增长                                      │
│   · 颜色/边框的状态切换（瞬时）                                │
│                                                             │
│   禁止的运动：                                               │
│   · 任何曲线路径                                             │
│   · 缩放（scale）——除了 3D 场景                               │
│   · 旋转（rotate）——除了 3D 场景                              │
│   · 淡入淡出（fade/opacity）——用平移或边框变化替代             │
│   · 弹性/弹跳（spring/bounce）                               │
│   · 任何贝塞尔缓动曲线                                       │
│                                                             │
│   节奏规则：                                                 │
│   所有动画时长必须是 120ms 的整数倍                            │
│   120ms / 240ms / 360ms / 480ms                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 工业节奏（Industrial Rhythm）

来源：PLC 控制器、机械冲压、电子继电器

```
不是 Material Design 的 "200ms" 统一节奏，
而是像机器一样有节拍：

   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
   │ 120  │   │ 120  │   │ 240  │   │ 120  │
   │ 进场  │   │ 停顿  │   │ 展开  │   │ 就位  │
   └──────┘   └──────┘   └──────┘   └──────┘

   啪 ... 啪 ... 啪——啪 ... 啪
   机械冲压的节奏，不是钢琴的节奏
```

**时长表（全部 120ms 的整数倍）：**

| 动作 | 时长 | 说明 |
|------|------|------|
| 边框状态切换 | 0ms（瞬时） | 颜色变化不需要时间 |
| 微小位移（hover） | 120ms | 2-4px 的平移 |
| 模块入场 | 240ms | 正交滑入 |
| 结构线绘制 | 360ms | 横线/竖线从一端到另一端 |
| 数据扫描填充 | 480ms | 逐行填充表格或列表 |
| 页面过渡-遮罩 | 360ms | 正交遮罩滑过 |
| 页面过渡-重组 | 480ms | 新页面的模块依次入场 |
| 图表渲染 | 600ms | 坐标轴 → 刻度 → 数据 |

### 4.3 构成主义运动（Constructive Motion）

来源：构成主义的"建造"隐喻

元素不应该"出现"——它们应该"被建造"。

```
Phase 1: 框架            Phase 2: 填充

┌──────────────────┐     ┌──────────────────┐
│                  │     │ ████████████████ │
│                  │     │ ████████████████ │
│                  │     │ ████████████████ │
│                  │     │ ████████████████ │
└──────────────────┘     └──────────────────┘
  边框先行                 内容填充
  120ms                   240ms 后

Phase 3: 编号            Phase 4: 数据

┌──────────────────┐     ┌──────────────────┐
│ ████████████████ │     │ ████████████████ │
│ ████████████████ │     │ 24  ████████████ │
│ ████████████████ │     │ +12% ███████████ │
│ A-01 ███████████ │     │ A-01 ███████████ │
└──────────────────┘     └──────────────────┘
  编号标签出现             数据填充就位
  360ms                   480ms
```

**构成主义运动规则：**
1. 每次运动是**可辨识的阶段**，不是连续的缓动
2. 阶段之间有微小停顿（"机械节拍"）
3. 运动方向固定：结构线从左到右或从上到下，填充从底部到顶部或从左侧到右侧
4. 编号和数据在框架之后出现，暗示"先有结构，后有内容"

### 4.4 正交运动（Orthogonal Motion）

来源：工业机械臂、XY 绘图仪、数控机床

```
所有运动只能是水平或垂直方向。

禁止：↗ ↘ ↙ ↖
允许：→ ← ↑ ↓

折线运动：
  → → → ↓
  不是 ╰（曲线）

正确：
  ────────
          │
          │
          ▼

错误：
  ╭──────╮
  │      │
  │      ▼
  ╰──────╯
```

**正交运动规则：**
1. 所有过渡：元素沿 X 或 Y 轴平移
2. 需要拐弯时：完成水平运动 → 微小停顿（120ms）→ 开始垂直运动
3. 不是 LERP 曲线——是分段匀速
4. 运动方向携带语义：
   - `→` = 前进、展开、进入
   - `←` = 后退、收起、退出
   - `↓` = 展开详情、下拉
   - `↑` = 收起详情、提交

```
  Module A ──→ 就位    240ms
       │

  Module C ──→ 就位    240ms
```

适用于：仪表盘加载、多卡片页面首次渲染

#### 4.5.4 Information Scan（信息扫描）

```
  ███░░░░░░░░░░░░░░    ← 扫描线从上到下
  ██████░░░░░░░░░░░
  ██████████░░░░░░░
  ██████████████░░░
  █████████████████

  不是旋转的 spinner
  而是一条水平线从上到下扫描过内容区
  扫过的地方"激活"（从线框变为实体）
```

适用于：数据表格加载、列表加载、搜索结果加载

#### 4.5.5 Pipeline Loading（管道加载）

```
  DATA ──→ [管道] ──→ NODE ──→ [管道] ──→ CARD

  数据以可见的"包"形式沿管道流动
  管道是水平/垂直的直角折线
  每个节点短暂停留（120ms）
  最终到达目标卡片，卡片被"激活"
```

适用于：搜索、筛选、数据刷新

### 4.6 悬停语言（Hover Language）

不是 Material Design 的"浮起"——而是**机械设备的微响应**。

```
  普通按钮 hover：
  ┌────────────┐          ┌────────────┐
  │   确认      │   →      │   确认      │
  └────────────┘          └────────────┘
                            编号亮起
                            边框加粗 1px→2px
                            轻微右移 2px

  卡片 hover：
  ┌──────────────────────┐
  │ A-03                 │  ← 编号从 text-tertiary 变为 accent
  │ ──────────────────── │  ← 标题下划线从 border-base 变为 accent
  │                      │
  │ 内容...              │  ← 内容不变
  │                      │
  └──────────────────────┘
   边框: border-base → border-strong
   整体: 向右平移 3px（正交运动）
```

**悬停微响应序列：**
1. 编号颜色变化（0ms）← accent 色瞬间亮起
2. 边框加粗/变色（0ms）
3. 元素整体平移 2-3px（120ms）← 正交方向
4. 如果有关联信息（tooltip/详情），在平移完成后出现（240ms）

### 4.7 页面过渡语言（Page Transition）

不是 Fade 300ms —— 而是**空间重组**。

```
  Phase 1: Grid (120ms)
  ┌──────────────────────────────┐
  │ ·  ·  ·  ·  ·  ·  ·  ·  ·  │  ← 目标页面的网格参考面淡入
  │ ·  ·  ·  ·  ·  ·  ·  ·  ·  │
  └──────────────────────────────┘

  Phase 2: Mask (360ms)
  正交遮罩从右向左滑过屏幕
  覆盖当前页面
  不透明，纯色 bg-base

  Phase 3: Modules (480ms)
  新页面的模块依次从右滑入
  大的先入 → 小的后入
  Hero 模块最先到达

  Phase 4: Numbers (120ms)
  编号标签瞬间出现（在每个模块就位时）

  Phase 5: Complete
  结构线最后绘制（360ms）
  从左上角开始，横线 → 竖线 → 坐标标记
```

## 六、页面节奏（Page Rhythm）

### 6.1 视觉比重分配

每个页面的视觉重量不应该均匀分配：

```
  ┌─────────────────────────────────────────────────────┐
  │                                                     │
  │   70%                        30%                    │
  │   呼吸空间                     内容区域               │
  │                                                     │
  │   · 网格                       · 卡片               │
  │   · 结构线                      · 数据               │
  │   · 编号                       · 交互               │
  │   · 空白                       · 图表               │
  │                                                     │
  │   来源：06 红色界面的核心吸引力——                      │
  │   只有 30% 内容，70% 是呼吸                           │
  │                                                     │
  └─────────────────────────────────────────────────────┘
```

**页面内容密度指南：**

| 页面类型 | 内容占比 | 说明 |
|---------|---------|------|
| 仪表盘（总览） | 40% | 4-6 个卡片，大面积留白 |
| 数据列表（表格） | 60% | 表格占主区域，周围留白 |
| 详情页 | 50% | Hero 信息 + 次要信息 |
| 表单页 | 50% | 表单居中，两侧留白 |
| 3D 场景 | 30% | 模型为主，信息叠加 |

### 6.2 空白不是"没东西"

空白的角色：

1. **结构线穿过空白** —— 空白中有制图的网格
2. **编号悬浮在空白中** —— 从卡片到编号之间是结构线的引导
3. **空白制造张力** —— 一个 80px 的数字旁边是 400px 的空白，这是海报的语言
4. **空白不是纯色** —— 可以有极淡的工程网格点阵

## 八、实施优先级

### Phase 1：基础（07 已定义）
- 色板、字体、卡片、按钮、输入框、表格、图表
- **目标：** "一个暗黑锐利的 SaaS"

### Phase 2：编号 + 结构线（1 周）
- 每个页面添加 MODULE-NN 编号
- 添加至少一条贯穿的结构线
- 页面底部添加版本标识
- **目标：** "像一个工程产品的界面"

### Phase 3：构图改造（1-2 周）
- 仪表盘改为不对称布局（Hero 卡片 + 次要卡片）
- 引入超大字体标题/数字
- 调整内容密度（增加留白）
- **目标：** "有海报感的工具界面"

### Phase 4：运动系统（2-3 周）
- 实现 Orthogonal Motion 工具函数
- 替换所有过渡动画为正交平移
- 实现 CAD Loading / Assembly Loading
- 实现悬停微响应序列
- 实现页面过渡：Grid → Mask → Modules → Complete
- **目标：** "先锋主义在运动中显现"

### Phase 5：3D 空间标注（1-2 周）
- 3D 场景添加坐标轴和尺寸标注
- 数据流添加节点编号和流向标签
- 空间编号与页面编号系统统一
- **目标：** "像建筑施工图的空间界面"

### Phase 6：打磨与一致性（持续）
- 审查所有页面——构图、留白、节奏
- 审查所有动画——方向、时长、节奏
- 确保可用性底线不被先锋主义破坏
