## 一、风格定义

### 主风格：Bento Box 企业级 UI

Bento Box 是近年 Apple 推广的布局范式：将信息组织为大小不一的矩形卡片，像日式便当盒一样排列。本设计将 Bento 布局应用于复杂的企业工作流可视化。

### 子风格特征

| 子风格 | 权重 | 表现 |
|--------|------|------|
| **Bento 网格布局** | ★★★★★ | 大小不一的卡片组成灵活网格，非对称但有序 |
| **流程图/旅程可视化** | ★★★★★ | 水平流程图为页面核心，连接线表示数据流向 |
| **浮动工具栏** | ★★★★☆ | 窄垂直图标栏悬浮在内容区左侧 |
| **多面板层叠** | ★★★★☆ | 上下叠加多个功能面板，不同内容密度共存 |
| **状态指示系统** | ★★★★☆ | 颜色编码状态球、实线/虚线连接线、进度节点 |
| **按钮矩阵** | ★★★☆☆ | 2×3 紧凑网格排列的操作入口 |

### 整体情绪

**有序、高效、成熟。** 将复杂的客户支持工作流呈现得可控且可导航。柔和的冷色调 + 圆角降低认知负荷，让企业工具拥有消费级应用的"干净感"，同时保留企业工具所需的"数据密度"。

## 二、布局结构

### 顶层框架

```
┌──────────────────────────────────────────────────────────────┐
│                    GLOBAL HEADER (顶部导航栏)                   │
│  Logo  | 主导航链接×7  |  搜索 🔍  |  通知 🔔  |  用户头像       │
├──────────────────────────────────────────────────────────────┤
│              CONTEXTUAL HEADER (次级标题栏)                     │
│         "Customer Journeys" 标题  |  用户头像组                  │
├────┬─────────────────────────────────────────────────────────┤
│    │              MAIN FLOW (中央流程图)                        │
│    │  ┌──────────┬──────────┬──────────┬──────────┐          │
│ 浮 │  │ 阶段1     │ 阶段2     │ 阶段3     │ 阶段4     │          │
│ 动 │  │ Case     │ Issue    │ Technical│ New      │          │
│ 工 │  │ Allocat. │ Identif. │ Resolut. │ Tasks    │          │
│ 具 │  │          │          │          │ 2×3 Grid │          │
│ 栏 │  └──────────┴──────────┴──────────┴──────────┘          │
│    │         ← 实线 + 虚线连接线 →                               │
│    ├─────────────────────────────────────────────────────────┤
│    │              BOTTOM PANELS (底部面板)                     │
│    │  ┌────────────────────┬────────────────────┐            │
│    │  │  Suggested         │  Support Ticket    │            │
│    │  │  Knowledge (表格)   │  Journey (统计)    │            │
│    │  └────────────────────┴────────────────────┘            │
└────┴─────────────────────────────────────────────────────────┘
```

### 细节：Global Header

- **左：** Logo + 多级文字导航链接（Relationship, Opportunities, Leads, Calendar, Cases, Reports, Quotes）
- **活跃项：** 深黑/炭色背景高亮（如 "Cases" 使用黑色 Pill 形状）
- **右：** 搜索图标 → 通知铃铛（红色 Badge）→ 用户头像
- **高度：** ~56-64px

### 细节：Contextual Header

- **左：** 页面大标题 "Customer Journeys"
- **右：** 用户头像行（圆形，带红/蓝色状态点）
- **高度：** ~48-56px

### 细节：浮动左侧工具栏

- **位置：** 主内容区左侧，独立悬浮
- **宽度：** ~48-56px（仅容纳图标）
- **内容：** 纵向排列的图标按钮（添加、查看、收藏等）
- **样式：** 极简描边图标，圆角卡片包裹

### 细节：中央流程图（页面核心）

四个阶段列水平排列，列之间有连接线：

#### 阶段 1：Case Allocation
- 垂直列表项，每项包含图标 + 标题 + 简短描述
- 连接点（小圆节点）在每项右侧

#### 阶段 2：Issue Identification
- 类似的垂直列表
- 实线箭头从阶段 1 的节点引向本阶段节点

#### 阶段 3：Technical Resolution
- 中间节点 "Request Processing" 使用深色背景高亮（视觉焦点）
- 实线（已完成）+ 虚线（进行中/可选）混合连接

#### 阶段 4：New Tasks（特殊布局）
- **打破垂直列表模式：** 使用 2×3 紧凑网格
- 每个格子是圆角矩形按钮，包含图标 + 短标签
- 形成"操作按钮矩阵"的感觉

### 细节：连接线系统

- **实线：** 表示直接/已完成的数据流
- **虚线：** 表示潜在/可选路径
- **节点：** 小实心圆点，出现在连接点位置
- **颜色：** 浅蓝色系（`#3B82F6` 或类似）

### 细节：底部面板（两列）

#### 左 — Suggested Knowledge
- 表格视图
- 列：标题、类型、相关度
- 紧凑行布局

#### 右 — Support Ticket Journey
- 统计可视化区
- 可能包含迷你图表或进度环

## 三、色彩体系

### 角色色板

| 角色 | 色值 | 用途 |
|------|------|------|
| 主背景 | `#F0F2F5` | 整页底色，冷灰 |
| 卡片表面 | `#FFFFFF` | 所有内容面板 |
| 活跃导航 | `#1A1A1A`（深黑） | 顶部导航当前项背景 |
| 连接线 | `#60A5FA`（浅蓝） | 流程图实线/虚线 |
| 执行状态 | `#3B82F6`（中蓝） | "Executed" 状态球 |
| 提醒/通知 | 红色/Salmon | 头像上的通知 Badge、"Active" 状态环 |
| 成功 | 绿色 | 次要成功状态（不突出） |
| 主文字 | `#1A1A1A` | 标题 |
| 次文字 | `#6B7280` | 描述、标签 |

### 色彩原则

- **冷色调主导：** 白 + 灰 + 蓝，传递专业与信任感
- **蓝色作为流程引导色：** 所有连接线和状态节点统一蓝色，形成视觉引导线
- **红色仅用于通知：** 面积小、位置精确（Badge 圆点），不会喧宾夺主
- **深色对比：** 活跃导航项和关键流程节点使用深黑，形成强烈的焦点-背景对比

## 四、字体排版

### 字体家族

**首选：** Inter / SF Pro / Product Sans  
**特征：** 现代无衬线，几何感，清晰可读

### 字重阶梯

| 层级 | 字重 | 大小 | 用途 |
|------|------|------|------|
| L1 | Bold/Black | 24-28px | 页面大标题（如 "Customer Journeys"） |
| L2 | Bold 600-700 | 18-20px | 区域标题 |
| L3 | Medium 500 | 14-16px | 卡片标题、列表项标题 |
| L4 | Regular 400 | 13-14px | 正文描述 |
| L5 | Regular 400 | 11-12px | 辅助元数据、时间戳 |

### 排版原则

- **大小缩放明确：** 从 24px+ 标题到 12px 元数据，共 5 级清晰层级
- **列表项双行布局：** 标题行（Medium）+ 描述行（Regular、灰色），标准信息密度
- **紧凑但可读：** 行高 1.3-1.4，不浪费空间也不拥挤

## 五、间距与边框

### 圆角系统

| 元素 | 圆角 | 说明 |
|------|------|------|
| 内容面板/卡片 | 12-24px | 高圆角，Pill-like 模块感 |
| 按钮 | 8-12px | 圆角矩形 |
| 流程节点 | 50%（圆形） | 连接线端点 |
| 头像 | 50%（圆形） | 用户头像 |
| 按钮矩阵项 | 12-16px | "New Tasks" 的格子项 |

### 阴影

```
/* 标准卡片 */
box-shadow: 0px 2px 16px rgba(0, 0, 0, 0.04);

/* 更柔和的扩散 */
box-shadow: 0px 4px 20px rgba(0, 0, 0, 0.03);
```

### 间距尺度

| 间距 | 值 | 用途 |
|------|-----|------|
| XS | 8px | 紧密关联元素 |
| S | 12px | 列表项内间距 |
| M | 16-20px | 卡片内边距、网格间距 |
| L | 24px | 区域间距 |
| XL | 32px+ | 大区块间距 |

### 分割线

**极少的可见边框。** 替代方案：
- 卡片通过背景色差异和阴影区分
- 列表项之间仅靠间距分离
- 流程图列之间靠连接线 + 间距分离
- 极少数情况使用 `1px solid rgba(0,0,0,0.05)` 微分割

## 六、标志性视觉元素

### 1. 流程图连接线网络

**这是整个设计的核心差异化特征。** 细蓝线（~1-2px）连接不同阶段的节点：
- 实线 = 直接/已完成流向
- 虚线 = 潜在/可选流向
- 起止点有实心圆节点
- 线可能有轻微的曲率而非严格的直角折线

### 2. 头像 + 状态 Badge

顶部导航中一行圆形头像，每张右下角带有小彩色圆点（红/蓝），表示在线状态或分配状态。

### 3. 拖拽手柄

列表项右侧的 "⋮⋮" 或 "⋯" 图标模式，暗示可拖拽排序。

### 4. 按钮矩阵（Button Bank）

阶段 4 "New Tasks" 打破纵向流程，使用 2×3 网格的紧凑按钮阵列：
- 每个按钮是独立的圆角矩形
- 包含图标 + 短文本标签
- 均匀分布，视觉像一个"操作面板"

### 5. 深色模式切换图标

左下角的深色圆形图标（太阳/星星符号），暗示深色模式切换或辅助功能菜单。

### 6. 双层导航结构

Global Header（全局导航）+ Contextual Header（页面上下文）双层顶部结构，清晰分离"去哪"和"在哪"。

## 七、适用场景

- **企业工作流可视化**（CRM、工单系统、供应链）
- **客户旅程地图**
- **项目管理看板**
- **多阶段流程监控**

## 八、与 Terminal Brutalist 的差异

| 维度 | Bento Enterprise | Terminal Brutalist |
|------|-----------------|-------------------|
| 圆角 | 大圆角 (12-24px) | 无或极小 (0-4px) |
| 布局原则 | Bento 非对称网格 | 等宽字体驱动的规整布局 |
| 连接线 | 曲线/圆角折线 | 直角/ASCII 风格线 |
| 按钮 | Pill 圆角、柔和 | 锐利矩形边框 |
| 色彩 | 冷灰白 + 蓝点缀 | 深暗底 + 高对比 |
| 情绪 | 成熟企业、亲和 | 硬核极客、原始 |

## 九、可借鉴元素（用于 Talos）

1. **流程图连接线系统** — 可适配为直角/ASCII 风格的设备流转可视化
2. **双层导航结构** — 全局 Header + 页面 Context Header 的信息架构
3. **按钮操作矩阵** — 紧凑的 2×N 操作入口，适合快捷操作区
4. **拖拽排序模式** — 订单/设备列表的排序交互
5. **阶段-状态映射** — 用视觉区分"已完成/进行中/待处理"阶段
6. **底部信息面板** — 将辅助信息（日志、统计）放在主流程下方的布局策略
