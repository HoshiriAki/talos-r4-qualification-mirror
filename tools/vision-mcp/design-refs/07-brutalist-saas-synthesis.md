## 一、风格定义

### 主风格：Brutalist SaaS（粗野企业风）

一种将**建筑粗野主义的原始几何诚实感**与**现代 SaaS 的数据密度和可用性**结合的设计系统。它不是"美化粗野主义"，而是让粗野主义变得可用——保留锐利、保留诚实、保留工业感，同时引入卡片系统、层级排版、清晰交互状态和数据可视化语言。

### 核心张力

```
粗野主义 ←——————————————————————→ 现代 SaaS
  锐利                                可读
  原始                                精致
  极限制色                              丰富层次
  反装饰                                数据可视化
  诚实结构                              交互反馈
  工业隐喻                              用户体验

        Brutalist SaaS 在这个光谱上的位置：
        粗野主义占 60% · SaaS 占 40%
```

### 子风格构成

| 子风格 | 来源 | 权重 | 在合成中的角色 |
|--------|------|------|---------------|
| **锐角几何** | 06 Isometric Brutalism | ★★★★★ | 全局 0px 圆角，绝对无阴影，结构至上 |

### 整体情绪

**严谨、锐利、工业智慧。** 像一个在冷战地堡里运营的顶级数据分析机构——混凝土墙内是最先进的 SaaS 工具。它是高效的，但拒绝用圆角和阴影来假装友好。它用清晰的边框、诚实的结构和精确的排版赢得信任。

## 三、色彩体系

### 3.1 设计原则

```
        SaaS 系                          Brutalist 系
  多级灰阶 + 多强调色    ──── 融合 ────→   限制色板 + 严格角色
  色彩丰富 = 信息量大                    每个颜色必须有结构意义
```

**Brutalist SaaS 的用色铁律：**
1. 每一个色值必须有一个明确的**结构角色**
2. 不允许"装饰性"的颜色
3. 强调色仅一种，且仅用于交互状态和关键数据
4. 灰阶精确为 6 级，每级间距相等，覆盖从深黑到白

## 五、字体排版

### 5.1 字体家族 — 双字体策略

这是融合的核心妥协之一：

| 用途 | 字体 | 理由 |
|------|------|------|
| **标题 / 数据 / 导航 / 代码** | **Space Mono** | 保留粗野主义的等宽基因 |
| **正文 / 表格内容 / 长文本** | **Inter**（或系统无衬线） | 确保 SaaS 场景下的可读性 |

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   Space Mono                 Inter                         │
│   标题 "DASHBOARD"           正文 "订单 #2394 已于昨日..."    │
│   数据 "$24,890"            表格 "张三 / 186****1234"       │
│   导航 "DEVICES"            表单标签 "客户姓名"              │
│   代码/ID "ORD-20260705"    提示 "请输入有效的手机号"         │
│                                                             │
│   粗野主义的骨骼               SaaS 的肌肉                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**规则：**
- 所有标题级别、数字读数、导航文字、代码/ID = Space Mono
- 所有正文段落、表格内容、表单标签、描述文字 = Inter
- 按钮文字根据上下文：主要 CTA 用 Space Mono（结构感），次要操作用 Inter（可读性）

### 5.2 字重与大小阶梯

| 层级 | 字体 | 字重 | 大小 / 行高 | 用途 |
|------|------|------|-------------|------|
| **H1** | Space Mono | 700 | 28px / 1.2 | 页面主标题 |
| **H2** | Space Mono | 700 | 22px / 1.3 | 区域标题 |
| **H3** | Space Mono | 600 | 16px / 1.4 | 卡片标题 |
| **KPI** | Space Mono | 700 | 36px / 1.1 | 核心指标大字 |
| **DATA** | Space Mono | 600 | 18px / 1.3 | 次要数据读数 |
| **Body L** | Inter | 500 | 15px / 1.5 | 正文、列表项 |
| **Body** | Inter | 400 | 14px / 1.5 | 表格内容、描述 |
| **Body S** | Inter | 400 | 12px / 1.5 | 辅助文字、时间戳 |
| **Caption** | Space Mono | 500 | 11px / 1.4 | 标签、全大写标识 |
| **Code** | Space Mono | 400 | 13px / 1.6 | 代码块、订单号、设备号 |

### 5.3 排版原则

1. **Space Mono 的视觉锚点作用：** 页面中所有 Space Mono 元素是结构的"骨架"，它们告诉眼睛"这里有关键信息"
2. **Inter 的流式阅读作用：** 表格行、长描述、表单标签使用 Inter 确保不疲劳
3. **数字必须等宽：** 用 Space Mono 天然保证所有数字对齐
4. **标题使用全大写可选：** H1 和 Caption 级别推荐全大写，中间级别不强制
5. **字重跳跃：** KPI (700) 对 Body (400) 的粗细比 = 1.75:1，形成强烈但诚实的对比（不靠颜色和阴影）

## 六、交互状态

### 6.1 状态定义 — 无阴影运动

Brutalist SaaS 禁止用阴影表示交互状态变化。替代方案：

| 状态 | 表现形式 | 示例 |
|------|---------|------|
| **默认** | `1px border-base` | 标准卡片 |
| **悬停** | `border → border-strong` + 微弱背景变化 | 边框加亮 + 背景变 `bg-elevated` |
| **聚焦** | `border → 2px accent` | 输入框获得 2px 强调色边框 |
| **激活/选中** | `border → 2px accent` + 左侧 3px accent 色条 | 导航项、列表行 |
| **按下** | 背景反转（亮↔暗）或 2px 内移 | 按钮按下时文字/背景色反转 |
| **禁用** | `opacity: 0.35` + `cursor: not-allowed` | 不可用按钮 |
| **加载** | 边框虚线动画或进度条 | 卡片边框变为虚线跑马灯 |

## 十、响应式策略

### 桌面（≥1280px）
- 完整侧边栏 + 多列网格
- 所有卡片可见

### 平板（768-1279px）
- 侧边栏折叠为图标模式（48px 宽）
- 网格降为 2 列或单列
- 数据表水平滚动

### 手机（<768px）
- 侧边栏隐藏，顶部汉堡菜单
- 单列布局
- 卡片全宽
- KPI 卡片 2×2 网格

**响应式不变的原则：**
- 0px 圆角在任何断点不变
- 无阴影在任何断点不变
- 颜色体系在任何断点不变
- 字体切换在任何断点不变（手机端 Space Mono 比例可稍降）

## 十一、动效哲学

### 允许
- **即时状态切换（0-150ms）：** 边框颜色变化、背景色变化、文字颜色变化——瞬间完成
- **布局过渡（200-300ms ease）：** 卡片尺寸改变、网格重排
- **加载进度条：** 线性动画，边框虚线跑马灯

### 禁止
- **缓入缓出弹跳：** 不需要"愉悦"的弹性动画
- **淡入淡出透明度动画：** 用边框变化替代
- **阴影渐变动画：** 没有阴影所以也没有阴影动画
- **旋转/缩放装饰动画：** 每一个动画必须有功能性原因

### 原则
> "动效是结构变化的信号，不是装饰。"

## 十二、可访问性

### 对比度保证
| 关系 | 对比度 | 标准 |
|------|--------|------|
| text-primary (#FFF) / bg-base (#0D0D0F) | ~18:1 | AAA ✓ |
| text-secondary (#A0A0A8) / bg-surface (#161618) | ~6:1 | AA ✓ |
| accent (#FF453A) / bg-surface (#161618) | ~4.5:1 | AA ✓ |
| text-tertiary (#6A6A72) / bg-surface | ~3.5:1 | 仅用于装饰/禁用 |

### 焦点指示器
- 所有可交互元素必须有可见的 2px accent 边框聚焦状态
- 不使用浏览器默认的 outline（通常带圆角），自定义方形焦点框

### 色盲友好
- 状态信息从不单独依靠颜色传达
- 每个状态指示器配合文字标签
- 图标 + 颜色 + 文字三通道编码

   - `card` — 标准卡 (1px border-base)
   - `card-emphasis` — 强调卡 (2px border-strong)
   - `card-focus` — 焦点卡 (2px accent)
   - `card-warning` — 警示卡 (2px warning + 可选条纹)
2. 全局替换现有卡片为新的卡片系统

### Phase 3：组件改造（3-5 天）

1. **按钮：** 4 级按钮系统（primary/secondary/danger/ghost）
2. **输入框：** 锐角 + 2px 聚焦边框
3. **表格：** Space Mono 表头 + Inter 数据行 + 方块状态指示器
4. **导航：** 侧边栏 + Header 锐角改造
5. **数据可视化：** 柱状图锐角化、颜色映射到新色板

### Phase 4：粗野主义装饰（2-3 天）

1. 仪表盘背景可选网格覆盖层
2. 警示条纹图案（CSS background pattern）
3. 工程构造角（可选，低优先级）
4. 数据关系连线组件

### Phase 5：动效 & 打磨（1-2 天）

1. 替换现有过渡动画为即时/快速过渡
2. 加载状态：边框虚线动画
3. 全页面一致性审查

## 十四、核心设计决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | 双字体（Space Mono + Inter） | 纯粹的等宽字体降低长文本可读性，SaaS 场景必须妥协 |
| 2 | 6 级灰阶（非 2-3 级） | SaaS 的复杂信息层级需要更多灰度层级 |
| 3 | 保留边框而非纯色块分离 | 表单和表格场景下，边框有功能性价值 |
| 4 | 单一强调色 + 功能色 | 单一强调色保持粗野主义的纯粹性，功能色仅用于必要场景 |
| 5 | 0px 圆角，无例外 | 这是粗野主义的底线，头像也改为方形 |
| 6 | 卡片容器系统 | 从 SaaS 借来的最核心遗产，但卡片用边框而非阴影定义 |
| 7 | 禁止阴影，无例外 | 这是粗野主义与 SaaS 的最大分歧点，选择粗野主义侧 |
| 8 | 非 3D 等角环境 | 06 的等角 3D 不适合数据密度高的 ERP，降级为 2.5D 图表可选 |
